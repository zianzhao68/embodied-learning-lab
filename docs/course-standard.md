# 网页课程制作与验收标准

> 版本：v1.2（2026-08-30）
> 适用范围：`D:\vla\site` 下的所有 Astro 课程；`D:\vla\web` 为只读迁移参考。  
> 硬性要求：开始制作任何新课程前，必须先读取本文件和根目录 `README.md`；若用户提出新标准，先更新本文件与 README，再实施课程。

## 1. 单课结构

每节课按以下顺序组织：

1. 为什么要学：以机器人真实问题切入。
2. 学习目标：3～6 个可验证目标。
3. 先备知识：说明前置课程和必需基础。
4. 核心直觉：先用自然语言和图建立空间理解。
5. 记号约定：在推导前完整定义符号、坐标系和方向。
6. 公式与推导：分步推导，不直接给孤立结论。
7. 数值例子：至少一个可心算或可手算的例子。
8. 工程映射：对应感知、规划、控制或 VLA 实际链路。
9. 高频错误：给出诊断方法，而不只罗列错误。
10. 本课小结：5～8 条主动回忆提示。
11. 课程测试：即时反馈并解释错误原因。

## 2. 公式规范

### 2.1 统一记号

- 坐标系名称使用正体：`\mathrm{A}`、`\mathrm{B}`、`\mathrm{base}`、`\mathrm{camera}`。
- 矩阵使用大写粗体：`\mathbf{R}`、`\mathbf{T}`。
- 向量使用小写粗体：`\mathbf{p}`、`\mathbf{t}`。
- 转置使用正体上标：`\mathbf{R}^{\mathsf T}`。
- 坐标变换统一写成：`${}^{\mathrm{A}}\mathbf{T}_{\mathrm{B}}`。
- 首次出现时必须同时给出方向别名：

$$
{}^{\mathrm{A}}\mathbf{T}_{\mathrm{B}}
\equiv
\mathbf{T}_{\mathrm{A}\leftarrow\mathrm{B}}
$$

其含义固定为“把 B 系表达转换为 A 系表达”。不得在同一课程中切换左右乘、行向量或相反语义。

### 2.2 排版

- 行内公式只用于短符号；核心公式必须独立展示。
- 所有上下标必须使用完整花括号，不写 `^A`、`_B`、`\mathbf T` 等省略形式。
- 关键公式字号高于正文，并使用独立强调容器。
- 长公式在移动端必须可横向滚动，不能裁切。
- 矩阵维度、单位、输入输出坐标系必须在公式附近说明。
- 公式制作后必须人工检查桌面端和移动端截图，不能仅以“构建通过”作为验收。

## 3. 图例规范

- 每个空间/几何知识点至少包含一张原理图。
- 优先使用 SVG；需要理解旋转、视角或动态变化时再使用 Three.js。
- 坐标轴颜色固定：x 红、y 绿、z 蓝。
- 图中必须标注原点、坐标系名称、向量方向和关键变量。
- 图下必须有图注，正文必须解释读图顺序。
- 图片需要 `alt` 文本，缩放到手机宽度后仍可辨认。
- 宽图缩放后若文字过小，允许在图卡内部横向滚动并保持可读字号，但不得造成整个页面横向溢出。
- 图不能只追求装饰效果，必须直接服务于某个公式或工程结论。

## 4. 测试与记忆规范

每课至少 5 题，覆盖：

1. 概念复述；
2. 符号或公式含义；
3. 数值计算；
4. 变换/推导原因；
5. 工程诊断，多选优先。

标准：

- 80% 为首次通过线。
- 每题提交后给出正确性和原因解释。
- 测试成绩保存在浏览器 `localStorage`，并同步记录到根目录 `README.md`。
- 每个知识点按第 1、3、7、14 天主动回忆；复习不是重读正文。
- 连续两次低于 70%，暂停增加新知识，补充图解、最小实现和变式题。

## 5. 视觉与交互规范

- 风格：简约、专业、留白充分，避免花哨动画。
- 正文最大宽度约 820 px，保证长文可读性。
- 桌面端提供课程目录；移动端不遮挡正文。
- 颜色和强调层级统一，公式、提示、警告、测试具有稳定视觉语义。
- 学习进度仅作为辅助，不能替代根目录进度记录。

## 6. 技术验收清单

新课程发布前逐项确认：

- [ ] 已按本标准完成课程结构。
- [ ] 所有公式遵循统一记号，上下标和字号人工检查通过。
- [ ] 图例、图注和替代文本完整。
- [ ] 题目、答案、解释和多选逻辑正确。
- [ ] `npm run build` 通过。
- [ ] `npm audit` 为 0 个已知漏洞。
- [ ] 桌面端和移动端页面完成截图检查。
- [ ] 页面无明显控制台错误、断链或内容溢出。
- [ ] 根目录 `README.md` 已更新当前状态、产出、遗留和下一步。
